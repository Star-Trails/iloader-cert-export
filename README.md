# iloader-cert-export

A Windows app that exports the Apple Development identity iloader already uses as a password-protected `.p12` file, for importing into LiveContainer's JIT-less mode.

The interface ships in English, Simplified Chinese, Traditional Chinese (正體中文), Japanese and Korean. The selector in the header switches language at any time, and the choice is remembered; System default follows the Windows display language.

## Set a strong password

**The exported file contains your Apple Development signing key. Anyone who has both the file and its password can sign apps as your team until the certificate expires or is revoked.**

- **Choose a long, unique passphrase** — 16 characters or more, ideally generated by a password manager. **Do not reuse your Apple ID password.**
- **Keep the file and the password in separate places, and share neither.**
- **If the file or password may have leaked, revoke the certificate** in your Apple Developer account and let iloader create a new one.

**The app keeps the password in memory for the length of the export and writes it nowhere.**

## How it gets the certificate

iloader keeps the private key locally, in Windows Credential Manager or under `%APPDATA%\me.nabdev.iloader\`, and asks Apple for the matching certificate each time it signs. The temporary signed app is deleted afterwards, so the certificate is not left on disk.

This tool therefore signs in to Apple with the account and password iloader saved, asks for a verification code when Apple requires one, and downloads the certificate whose public key matches the stored private key. No device connection is involved.

It never creates, renews or revokes a certificate, and it leaves iloader's storage untouched.

## Prerequisites

- iloader has signed an app at least once under the same Windows user while signed in to the account, so the private key exists.
- iloader's save-credentials option was enabled during that sign-in. Without it there is no password to reuse, and the app stops with an explanation instead of prompting for one.
- A trusted device or phone number for the verification code, if Apple asks for one.
- Network access.

## Use

1. Download the Windows x64 ZIP from [Releases](https://github.com/Star-Trails/iloader-cert-export/releases) and extract it, keeping both executables together.
2. Open `iloader-cert-export.exe` as the Windows user that runs iloader.
3. Choose a saved account, **set a strong password** for the file, pick a folder, and select Export.
4. Move the `.p12` to the device, choose Import Certificate in LiveContainer, select the file and enter that password. Then check JIT-Less Mode Diagnose.

After writing the file, the app checks the certificate's validity dates and asks the issuer's OCSP responder whether it has been revoked. An answer it cannot confirm is reported as unknown.

## Build

Go 1.27.3 and a Rust toolchain with the MSVC linker, from the project root:

```powershell
go test ./...
cargo build --release --locked --manifest-path helper/Cargo.toml
go run github.com/egoist/mygo/cmd/mygo@v0.7.3 build -platform windows/amd64
Copy-Item helper/target/release/iloader-cert-helper.exe dist/windows-amd64/
```

The [release workflow](.github/workflows/release.yml) runs the same steps and writes the ZIP plus a SHA-256 checksum.

### Helper layout

Third-party Apple code is confined to one adapter, so a library upgrade stays local:

| File | Contents | Library it calls |
|---|---|---|
| `helper/src/protocol.rs` | line-delimited JSON between app and helper | serde |
| `helper/src/credentials.rs` | iLoader's credential-store reads | keyring |
| `helper/src/apple.rs` | sign-in, certificate listing, PKCS#12 | isideload |
| `helper/src/model.rs` | plain structs crossing module boundaries | none |
| `helper/src/main.rs` | wiring | none |

Every file here is written for this project. The exception is `apple.rs`, whose certificate lookup by public key and exclusive `.p12` naming are adapted from iloader-export (MIT, licence in [`helper/LICENSE`](helper/LICENSE)).

To upgrade `isideload`, change its version in `helper/Cargo.toml`, run `cargo build --release`, then fix whatever the compiler reports in `apple.rs` alone. The protocol in `protocol.rs` is what the Go side depends on; keep its field names stable or change both sides together.
